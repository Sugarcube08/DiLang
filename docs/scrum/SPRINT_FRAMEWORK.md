# DiLang Sprint Cadence & Ceremonies Framework

## 1. Cadence Structure

DiLang development follows a rigid **2-Week Sprint Cadence** starting on Mondays.

```
┌──────────────────────────────────────────────────────────────┐
│                    2-Week Sprint Cycle                       │
├──────────────────────────────┬───────────────────────────────┤
│           Week 1             │            Week 2             │
│ • Mon: Sprint Planning       │ • Mon-Thu: Core Feature Dev   │
│ • Daily Async Standups       │ • Fri AM: Code Freeze & QA    │
│ • Wed: Backlog Refinement    │ • Fri PM: Review & Retro      │
└──────────────────────────────┴───────────────────────────────┘
```

---

## 2. Ceremony Agenda

### 2.1 Sprint Planning (Monday W1, 60 mins)
- Select target backlog items matching sprint capacity velocity.
- Validate items against Definition of Ready (DoR).

### 2.2 Async Standup (Daily, 5 mins)
- Three questions answered in developer log:
  1. What did you complete yesterday?
  2. What will you complete today?
  3. Are there any architectural or hardware blockages?

### 2.3 Backlog Refinement (Wednesday W1, 45 mins)
- Deconstruct upcoming epics into PBIs.
- Estimate story points.

### 2.4 Sprint Review & Demo (Friday W2, 45 mins)
- Live demonstration of functional software build against Definition of Done (DoD).

### 2.5 Retrospective (Friday W2, 30 mins)
- Review velocity metrics, latency SLAs, and process improvements.
