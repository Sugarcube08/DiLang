# DiLang Engineering Principles

## 1. Core Tenets

DiLang is an open-source, local-first language learning system designed for multi-decade durability, absolute user data privacy, and real-time interactive intelligence.

---

## 2. Fundamental Architectural Rules

### Principle 1: Local-First & Offline Sovereignty
- **Zero Cloud Dependencies**: Core speech recognition (Whisper), speech synthesis (Piper), natural language understanding (Qwen3-0.6B Instruct), deterministic translation, FSRS flashcard scheduling, and vector retrieval MUST run entirely locally on the user's client hardware.
- **No Mandatory Accounts**: All user progress, speech recordings, metrics, and memory graphs remain stored strictly within local SQLite files under user ownership.

### Principle 2: Rigid Boundary Separation (Rust Core vs. Flutter UI)
- **Rust Core (`dilang_core`)**: Sole authority for business logic, database migrations, FSRS mathematical scheduling, model execution, and tokenization.
- **Flutter UI**: Pure reactive presentation layer. Flutter MUST NOT perform direct database queries, write custom SQLite drivers, or execute raw LLM inference directly in Dart.
- **Bridge Protocol**: Inter-process communication occurs exclusively via typed asynchronous contracts generated by `flutter_rust_bridge` (FRB v2).

### Principle 3: Predictable Latency & Zero UI Blocking
- **Non-blocking Rendering**: No long-running computation or I/O operation may ever take place on Flutter's main UI looper thread.
- **Async Streaming**: Large payload operations (audio chunk generation, LLM token streaming) must use FRB v2 `StreamSink` primitives to render response tokens instantly as generated.

### Principle 4: Deterministic Type Safety & Explicit Error Handling
- **No Swallowed Exceptions**: Rust `Result<T, E>` and `Option<T>` types must be preserved across the FRB boundary. Silently ignoring errors, returning dummy fallback stubs, or swallowing unhandled exceptions is strictly forbidden.
- **Strict Lint Enforcement**: Rust code must pass `cargo clippy -- -D warnings` with zero warnings. Dart code must pass `flutter analyze` under strict analysis options.

## 3. Engineering Metrics & Quality Gates

| Metric | Target Standard | Enforcement Point |
| :--- | :--- | :--- |
| **Rust Unit Test Coverage** | $\ge 85\%$ line coverage | CI Pipeline (`cargo tarpaulin`) |
| **Flutter Widget Test Coverage** | $\ge 80\%$ line coverage | CI Pipeline (`flutter test`) |
| **Cold Startup Time** | $< 1.2$ seconds to interactive state | Performance Benchmark |
| **UI Frame Rate** | Constant 60 FPS (120 FPS on high-refresh screens) | Flutter Performance Profiler |
| **Binary Memory Overhead** | $< 350$ MB RAM (excluding LLM weights) | System Benchmark |
